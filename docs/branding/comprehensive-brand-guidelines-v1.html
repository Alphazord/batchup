Section 01

Positioning

"WhatsApp is where your batch ended up. BatchUp is where your batch actually lives." Students already run their social lives across a dozen WhatsApp groups and one messy Discord server — BatchUp merges WhatsApp's speed and simplicity with Discord's roles, reactions, and admin control, in one app neither techy nor non-techy users have to learn twice.

Who this has to work for

  • Non-techy students — the person who's never touched Discord. Nothing here should require an explanation.
  • Techy students — the person who runs a 500-member Discord server and expects roles, rate limits, and real admin control.
  • Everyone in between — a class WhatsApp group's silent majority, who just wants messages to arrive fast and stay organized.

What "enterprise-grade" means here

  • Every screen in this document ships as real product UI — not a mood board. Component states (empty, loading, error, focus) are specified, not implied.
  • Desktop and mobile are designed as siblings, not a shrink-and-squeeze of one layout.
  • Accessibility, contrast, and reduced-motion are requirements, not a checklist added at the end.

Section 02

Logo & app icons

The mark reads three ways at once: a chat bubble, a roll-call tick, and a small "up" arrow. One geometry, reused everywhere from the wordmark to the smallest favicon.

App icon

iOS/Android home screen. Full-bleed lime square, no additional padding beyond the OS mask.

Adaptive icon (light)

Android adaptive icon foreground, inverted for light-surface launchers.

12

Notification badge

Marker-pink count badge, top-right of icon. Caps display at "99+".

Favicon / 16px

Below 20px the checkmark stroke thickens slightly so it doesn't disappear at browser-tab size.

Clear space

25% of the icon's width on every side, in both the icon-only mark and the full wordmark lockup. Nothing else sits inside that margin.

Minimum size

Icon-only: 20px. Full wordmark lockup: never below 96px wide, or "up" stops reading as a stamp.

Never

Recolor the bubble, unrotate the "up" stamp, reset the wordmark in another typeface, or add a drop shadow.

Section 09

Direct messages

Starting a DM never requires more than a username. No friend requests, no follow-back — anyone can message anyone, matching how a batch actually behaves.

Start a DM — two paths

  • Search by username in the sidebar search bar → tap "Chat"
  • Tap any username inside a group chat → jumps straight to (or creates) the DM

Conversation list rules

  • Sorted by most recent message, always — no manual reordering
  • Unread badge shows exact count up to 99, then "99+"
  • Typing state replaces the preview line only while active

Touch & gesture rules

Swipe to reply

Swipe right on any bubble to attach a reply — mirrors WhatsApp's muscle memory on purpose, since it's the one gesture nobody has to learn.

Long-press for actions

Long-press opens the react/reply/edit/delete sheet, replacing desktop's right-click context menu.

44px minimum touch target

Every tappable element — tab icons, chips, message actions — meets a 44×44px minimum hit area, even where the visible icon is smaller.

Section 13

Iconography

2px rounded stroke, consistent corner radius, filled only for an active/selected state. Motifs pull from the classroom and hostel-room vernacular — notebooks, highlighter strokes, attendance ticks, timetable grids — never generic tech clip-art.

Section 14

Voice & copy system

BatchUp talks like the funniest, most reliable person in the group chat — never a support ticket. Short sentences, real verbs, zero corporate padding.

  • Write like a person texting, not a system logging an event.
  • Errors explain what happened and what to do next — never "oops!" with no next step.
  • Never blame the user for a system failure; gently call out their own rate limit only.
  • One exclamation mark at most per string, and only when earned.
  • Buttons say the action, in the same words the confirmation echoes back.
  • BatchUp's voice appears only in system copy — never inside anyone's DMs or group messages.

Section 15

Accessibility

Non-negotiable floor for every screen in this document — not an audit pass added at the end.

AA+
Contrast — every text/background pairing in Section 03 meets WCAG AA at minimum; Paper-on-Ink and Highlighter-on-Ink exceed AAA.
44px
Touch targets — every tappable control on mobile meets a 44×44px minimum hit area, regardless of visible icon size.
Focus
Keyboard focus — every interactive element on desktop shows a visible 2px Highlighter focus ring; nothing relies on hover alone.
Motion
Reduced motion — `prefers-reduced-motion` swaps all slide/scale transitions for instant state changes; typing dots and loading spinners still animate minimally, never a jarring cut.
Labels
Screen readers — icon-only buttons (send, react, more) always carry an `aria-label` matching their visible tooltip text, not a generic "button."

Section 16

Do & don't

Do
  • Design mobile and desktop as siblings from the same components, not one squeezed into the other.
  • Use exactly one loud accent per screen as the hero color.
  • Keep every error, empty, and loading state specified before a screen ships.
  • Let usernames and timestamps render in mono for the "stamped" feel.
Don't
  • Don't ship a mobile screen that's just the desktop layout at 375px wide.
  • Don't reach for a blue-to-purple gradient hero — that's every other chat app's default.
  • Don't write error copy that apologizes without saying what to do next.
  • Don't treat accessibility as a post-launch pass.
